# 监控采样调度与并发

本说明纳入[v1.0.0工作树文档归档](../../docs/releases/v1.0.0.md)；公开V1及`schemaVersion=1`保持不变，归档不等同生产发布。

## 固定任务

| 任务 | AUTO入口 | 周期/在途 |
| --- | --- | --- |
| 股票报价 | `stock:source-control:v1:entry:monitor` | 120秒；最多三只股票，每次独立spawn源进程 |
| ETF报价 | `stock:source-control:v1:entry:etf` | 120秒；一次新浪全表，复用报价和字典缓存 |
| 市场指数/行业/概念 | `stock:source-control:v1:entry:quotes` | 120秒；最多三项在途，完成即发布 |
| 全市场即时资金 | `stock:source-control:v1:entry:funds` | 120秒；页数发现串行、两页滑动窗口，同批汇总/宽度/股票资金点 |

四个任务独立等待和执行，同任务不重叠。快轮等待下一个未来定点，慢轮达到120秒后在有效窗口内接续；不积压过期轮次、不补历史采样。市场完整刷新仍原子取得quotes/funds两个入口，忙时立即返回；资金优先提交，与指数/行业/概念四个候选并行，各自fork独立执行器，真实源配额仍生效；内部同步结果、超时及jobId契约不变。股票资料与报价仍共用monitor入口及原采样业务锁；ETF资料/字典/资产配置共用etf入口，批次串行。交易所字典使用reference入口。

日历使用独立calendar入口，月度及启动补建沿原业务限频；监控读取/补建日历不会申请市场行情入口。资金仍只读缓存。日历未知不得按工作日推断，AUTO不请求业务行情；休市/盘后MANUAL快照与历史点边界沿现有规则。

## 配额、等待和取消

AUTO跨入口全局最多6个源名额，THS/XQ各3个、SINA/交易所各2个，XQ包括蛋卷；30秒配额租约、10秒续租。来源HTTP启动间隔保持THS/XQ/交易所1秒、新浪0.2秒、THS基金资料额外2秒。Token、总闸、普通冷却与共享风险冷却保持原语义。

个股和市场行情的每个在途调用复制Provider并持有独立SourceExecutor，仅继承父批次锁、截止时间和取消信号，不共享可变批次状态。每次提交工作线程使用独立copy_context继承入口租约。迭代器关闭、业务写入失败或批次取消时停止全部在途执行器，等待TERM/KILL/reap，再退出任务；父流程独占标准化及Redis事务，不在线程中发布。

所有配额等待、初始化、HTTP限频等待及清理计入原源/批次预算。不新增内存采样或替代内存监控。

## 个股到期等待

AUTO每股每轮最多一次，先提交已到期项。父流程用Redis PTTL估算剩余时间，最多等待至本轮开始后60秒，等待计入原300秒批次预算且不占源名额。等待期内观察到将于60秒内到期的项保留资格；即使三个并发位忙到100秒，这些项也可以在剩余300秒预算内提交。预计70秒才到期的项在60秒截止后跳过，不能因其他慢股票在途而延长自身到期等待。实际源前120秒门禁及<=5秒最终保护仍有效，避免配置资料等并发请求改变间隔后提前调用。MANUAL不读取AUTO单股间隔。

## 固定即时资金两页适配

只针对AKShare 1.19.1的`stock_fund_flow_individual(symbol="即时")`及`data.10jqka.com.cn/funds/ggzjl/field/{code,zdf}/order/desc/page/{page}/ajax/1/free/1/`精确路径。发现总页数的请求串行；同一函数内采用最多两页滑动窗口，请求中和完成但未消费页共同计数；消费前页后即补下一页，不并行重复调用整个函数，不修改安装包。分页URL改为稳定code倒序，按页码交付，原AKShare负责HTML表格解析与DataFrame合并。行业/概念和其他参数不使用此适配。

两条固定执行通道各自独占一个批次级持久Session，复用连接，并在所属线程关闭；原请求头、代理、证书及超时选项保持。原调用当前页使用AKShare生成的`hexin-v`，预取页通过原模块`ths.js`与MiniRacer流程独立生成签名；Linux旧MiniRacer没有close时沿对象回收，保留已修复的平台差异处理。每页只有一次实际请求；仅保留当前两页原响应，已解析旧响应在下次请求时清空。AUTO额外页尝试原子获取一个全局/THS名额，无空闲时直接串行继续，不排队等待额外名额。额外租约每10秒续租，HTTP完成释放；源进程被强制取消/超时回收后，父进程按`源token:page`所有权清理其残留名额，不能误删其他持有者。

两路共享实际HTTP速率键，THS启动间隔仍>=1秒；共享逻辑采集身份，只有该函数首个HTTP设置120秒门禁和采样时刻。长批次超过120秒时，后续页不重新占位。完整页数、页码、稳定代码顺序、无重复/冲突、行数和金额校验通过后，才同批生成资金汇总、宽度及选中股票资金点，并一次事务发布；失败保留历史，不输出部分汇总，collectedAt采用真实批次完成时间。

## 120秒门禁

120秒最低间隔在首个实际HTTP启动许可时原子设置；等待配额、初始化、没有启用监控或日历未知不提前占位。间隔剩余<=5000毫秒时在当前预算内等待，较长立即跳过，不提前请求、不立即失败重试。

股票沿用`stock:monitor:v1:sample:lastRequest:{symbol}`，ETF沿用`stock:etf-monitor:v1:min-interval`。市场原quotes/funds内部间隔键、完整刷新`stock:market:v1:min-interval`按实际HTTP更新；同批令牌允许后续模块进入，各模块新增内部`stock:source-control:v1:interval:market:{module}`最低间隔，避免模块乱序绕过120秒保护。后续物理HTTP不重复占该函数的首请求间隔，但继续服从共享HTTP速率。

新增内部`stock:source-control:v1:sample-time:*`仅记录HTTP采样间隔（TTL一天），不参与业务数据或公共V1契约。MANUAL不读写AUTO间隔/配额/入口，仍共享HTTP速率及风险控制，使用独立调用状态。

## 发布和日志

成功股票/模块完成即发布，乱序完成不改变配置或规范化列表排序。市场WATCH每次重读最新快照，只合并变化模块，首次加3次重试；版本链和通知同事务。股票按源时间去重/拒绝旧报价，最近历史保留规则、严格源时间>15:00收盘确认保持。资金同批点不重复。ETF没有可靠源时间，不虚构sourceTime或资金点。

日志分别记录初始化、源配额等待、HTTP共享限速/短间隔等待、网络请求累加、分页审计、记录转换、标准化和发布。原“源请求耗时”改为“AKShare函数执行耗时”；原签名/解析/拼接未分别测量，记录为函数执行减去主调用传输包装的剩余耗时，不误标为网络。页日志说明串/并行、页码及窗口；批次记录页数/请求数、额外名额取得次数及等待时间。并行通道的网络/等待累加值不能相加推断墙钟耗时。成功结果先最多0.2秒自然退出等待，再TERM/KILL，仍计入原清理预算；日志区分成功后清理、失败、取消和超时，强制回收后按所有权释放额外租约。不输出正文或凭据。前端仍按180秒断线判断，本次不修改其阈值；慢源、配额竞争、风控与网络故障仍可能造成超过180秒缺口，不保证生产及时性，不补造点。

## 验证边界

本轮离线模拟覆盖两条持久Session/线程隔离、两页滑动窗口、乱序交付、串行回退、取消/超时/租约失效清理，及原AKShare解析前后结果与请求次数一致；完整市场四候选资金优先、快模块先发布、连续版本、资金点去重和失败保留历史。加速分页模拟采用固定延迟，不代表真实源收益。既有临时离线模拟还覆盖六路/分组配额、三股三模块、60/300秒边界、并发位忙至100秒时到期资格、等待不占名额、两页竞争/无名额串行、逐页一次、签名来源、原AKShare解析结果一致、额外租约强制回收及长批次不重置首请求门禁；原有模拟覆盖四任务入口隔离/完整市场原子锁、全局6/THS及XQ3/其他来源2、十股三路及乱序交付、独立spawn及双源取消回收、实际HTTP间隔及120秒门禁、<=5秒等待/预算边界、ETF全表及字典复用、日历未知/休市/盘后边界、旧报价拒绝/去重/严格收盘确认、事务版本链/资金点去重、九个内部路由认证和模式校验。仅用fake Redis、mock及spawn模拟源，Python语法和差异另行检查。未调用真实源或生产Redis、未部署；服务器容量和源站限流效果需部署后观察真实日志。
