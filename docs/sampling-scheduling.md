# 监控采样调度与并发

## 固定任务

| 任务 | AUTO入口 | 周期/在途 |
| --- | --- | --- |
| 股票报价 | `stock:source-control:v1:entry:monitor` | 120秒；最多两只股票，每次独立spawn源进程 |
| ETF报价 | `stock:source-control:v1:entry:etf` | 120秒；一次新浪全表，复用报价和字典缓存 |
| 市场指数/行业/概念 | `stock:source-control:v1:entry:quotes` | 120秒；最多两项在途，完成即发布 |
| 全市场即时资金 | `stock:source-control:v1:entry:funds` | 120秒；分页串行，同批汇总/宽度/股票资金点 |

四个任务独立等待和执行，同任务不重叠。快轮等待下一个未来定点，慢轮达到120秒后在有效窗口内接续；不积压过期轮次、不补历史采样。市场完整刷新仍原子取得quotes/funds两个入口，忙时立即返回；内部同步结果、超时及jobId契约不变。股票资料与报价仍共用monitor入口及原采样业务锁；ETF资料/字典/资产配置共用etf入口，批次串行。交易所字典使用reference入口。

日历使用独立calendar入口，月度及启动补建沿原业务限频；监控读取/补建日历不会申请市场行情入口。资金仍只读缓存。日历未知不得按工作日推断，AUTO不请求业务行情；休市/盘后MANUAL快照与历史点边界沿现有规则。

## 配额、等待和取消

AUTO跨入口全局最多3个源进程，同来源最多2个，XQ包括蛋卷；30秒配额租约、10秒续租。来源HTTP启动间隔保持THS/XQ/交易所1秒、新浪0.2秒、THS基金资料额外2秒。Token、总闸、普通冷却与共享风险冷却保持原语义。

个股和市场行情的每个在途调用复制Provider并持有独立SourceExecutor，仅继承父批次锁、截止时间和取消信号，不共享可变批次状态。每次提交工作线程使用独立copy_context继承入口租约。迭代器关闭、业务写入失败或批次取消时停止全部在途执行器，等待TERM/KILL/reap，再退出任务；父流程独占标准化及Redis事务，不在线程中发布。

所有配额等待、初始化、HTTP限频等待及清理计入原源/批次预算。不新增内存采样或替代内存监控。

## 120秒门禁

120秒最低间隔在首个实际HTTP启动许可时原子设置；等待配额、初始化、没有启用监控或日历未知不提前占位。间隔剩余<=5000毫秒时在当前预算内等待，较长立即跳过，不提前请求、不立即失败重试。

股票沿用`stock:monitor:v1:sample:lastRequest:{symbol}`，ETF沿用`stock:etf-monitor:v1:min-interval`。市场原quotes/funds内部间隔键、完整刷新`stock:market:v1:min-interval`按实际HTTP更新；同批令牌允许后续模块进入，各模块新增内部`stock:source-control:v1:interval:market:{module}`最低间隔，避免模块乱序绕过120秒保护。后续物理HTTP不重复占该函数的首请求间隔，但继续服从共享HTTP速率。

新增内部`stock:source-control:v1:sample-time:*`仅记录HTTP采样间隔（TTL一天），不参与业务数据或公共V1契约。MANUAL不读写AUTO间隔/配额/入口，仍共享HTTP速率及风险控制，使用独立调用状态。

## 发布和日志

成功股票/模块完成即发布，乱序完成不改变配置或规范化列表排序。市场WATCH每次重读最新快照，只合并变化模块，首次加3次重试；版本链和通知同事务。股票按源时间去重/拒绝旧报价，最近历史保留规则、严格源时间>15:00收盘确认保持。资金同批点不重复。ETF没有可靠源时间，不虚构sourceTime或资金点。

日志分别记录调度等待、源配额等待、短间隔等待、限频跳过、源失败、源时间未更新，以及HTTP/报价有效采样间隔，不打印凭据。前端仍按180秒断线判断，本次不修改其阈值；慢源、配额竞争、风控与网络故障仍可能造成超过180秒缺口，不保证生产及时性，不补造点。

## 验证边界

临时离线模拟覆盖四任务入口隔离/完整市场原子锁、全局3/同源2、十股两路及乱序交付、独立spawn及双源取消回收、实际HTTP间隔及120秒门禁、<=5秒等待/预算边界、ETF全表及字典复用、日历未知/休市/盘后边界、旧报价拒绝/去重/严格收盘确认、事务版本链/资金点去重、九个内部路由认证和模式校验。仅用fake Redis、mock及spawn模拟源，Python语法和差异另行检查。未调用真实源或生产Redis、未部署；服务器容量和源站限流效果需部署后观察真实日志。
